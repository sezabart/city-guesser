# Guess the City

A city-guessing game for the living room: eight photographs, seven choices each,
nothing but roofs, streets and skylines to go on. Built for a TV and a remote
control, and made of **plain HTML + one stylesheet — no JavaScript at all**.

## Play it

Open `index.html`. Or publish it (below) and point the TV browser at the URL.

- **← ↑ → ↓** move the highlight between answers
- **OK / Enter** confirms
- **1–7** jump straight to an answer (if the TV browser sends bare number keys)

The focused answer turns solid yellow with a white ring, so you can always tell
where you are from the sofa.

## Publish on GitHub Pages

```sh
git init
git add .
git commit -m "Guess the City"
git branch -M main
git remote add origin git@github.com:USER/REPO.git
git push -u origin main
```

Then in the repo: **Settings → Pages → Source: Deploy from a branch → main / (root)**.
The game appears at `https://USER.github.io/REPO/`. No build step, no Jekyll
config, nothing to configure — `index.html` is the entry point.

You can also drag the files into a repo through the GitHub web UI; the only
requirement is that `index.html`, `style.css` and `images/` stay together at the
same level.

## How it works without JavaScript

The score can't live in a variable, so it lives in the **filename**:
`q3-2.html` means "question 3, two correct so far". Answering links to
`q3-2-right.html` (score becomes 3) or `q3-2-wrong.html` (score stays 2), and each
of those links onward to the next question. Every state the game can be in is a
real, cacheable HTML page, which is why 256 possible playthroughs all work from
static files.

Pages are generated by `build.py` (~120 files). Edit the quiz there and re-run:

```sh
python3 build.py
```

`build.py` holds the quiz itself, at the top of the file: city, photo, one-line
fact, and the seven options. The first city listed in `choices` is always the
correct one; the order gets shuffled at build time with a fixed seed, so
rebuilding never rearranges the answers.

Adding a ninth question means adding an entry to `QUIZ` and setting
`QUESTIONS = 9` — the page count roughly triples because every (question, score)
state is generated.

## Files

| Path | What it is |
| --- | --- |
| `index.html` | Title screen |
| `q{1-8}-{score}.html` | A question, at a given score |
| `q{1-8}-{score}-right/wrong.html` | Verdict screen |
| `end-{0-8}.html` | Final score screen |
| `credits.html` | Photo attributions |
| `style.css` | The whole design, TV-sized |
| `build.py` | Generator (the only thing you edit) |
| `images/` | 1600×900 crops, pre-scaled for slow TV browsers |

## Design notes

- Sized in `vh`/`vw`, so the same layout works at 720p and 1080p, and the outer
  3–4% is kept clear for TVs that overscan the picture.
- No external fonts, no CDN, no CSS grid, no flex `gap`, no custom properties —
  the kind of CSS an older smart-TV browser is likely to actually support.
- Photos are 1600×900 JPEGs (~300 KB each) and the title screen prefetches all
  eight, so the game plays without waiting between questions.
- Photos are deliberately *not* postcard landmarks: Haussmann roofs, a Mong Kok
  street, apartment blocks along the Han. Distractors are cities on the same
  continent or with similar building stock.
